

RAG and Vector Databases
Retrieval-Augmented Generation (RAG)
What is RAG?
Retrieval-Augmented Generation (RAG) is a technique that combines the text generation capability of Large Language Models (LLMs) with information retrieval from external sources. This approach improves the accuracy and reliability of responses generated by AI models.
How it works?
The RAG process can be divided into three main steps:
Retrieval: 
When a query is received, the system searches an external database or knowledge source for relevant information.
This information may be stored as documents, text fragments, or structured data.
Semantic search techniques are used to find the most relevant content.
Augmentation: 
The retrieved information is combined with the original query.
An enriched context is prepared that includes both the question and the relevant information found.
Generation: 
The language model uses the augmented context to generate a response.
The response is based on both the model's general knowledge and the specific retrieved information.

Advantages of RAG
Improved Accuracy
Responses are backed by up-to-date and specific information.
Reduces "hallucinations" or incorrect information generated by the model.
Updatable Knowledge
The external knowledge base can be updated without retraining the model.
Allows keeping information always current.
Transparency
Information sources can be tracked and cited.
Improves reliability and verifiability of responses.
Common Applications
Virtual Assistants 
Customer service systems with access to specific documentation.
Research assistants that can query academic databases.
Documentation Systems 
Technical documentation search and query tools.
Enterprise knowledge management systems.
Research Tools 
Legal document and regulation analysis.
Scientific and medical research.
Implementation Considerations
Data Quality
Response quality depends directly on the quality of stored information.
It is crucial to maintain an accurate and up-to-date knowledge base.
Performance
The retrieval process must be efficient to maintain acceptable response times.
A good indexing and search strategy is required.
Costs
Implementation may require significant storage and processing resources.
It is important to consider the balance between accuracy and efficiency.

Vector Databases and Embeddings
What is a Vector Database?
A vector database is a specialized system designed to store and efficiently search high-dimensional vectors. These vectors are numerical representations (embeddings) of data such as text, images, or audio in a multidimensional mathematical space.
Key Characteristics of Vector Databases
Vector databases are distinguished by two fundamental characteristics: their unique data structure and their similarity search capability. These characteristics make them especially suitable for modern artificial intelligence and data processing applications.
The data structure in these databases is fundamentally different from traditional databases. Instead of storing data in conventional formats like text or individual numbers, vector databases work with fixed-length numerical vectors. These vectors are precise mathematical representations where each element has the same number of dimensions, typically ranging from 100 to over 1000 dimensions. This uniform structure is not arbitrary; it is specifically designed to optimize similarity searches in multidimensional spaces, enabling efficient operations that would be extremely complex or impossible with traditional data structures.
Similarity search represents another distinctive and crucial characteristic of these databases. Unlike exact searches in traditional databases, vector databases employ approximate nearest neighbor (ANN) search algorithms. These algorithms are designed to find similar elements based on the distance between vectors in the multidimensional space. To calculate these distances, several mathematical methods are used, each with its own advantages depending on the use case. Cosine distance, for example, is excellent for measuring similarity regardless of vector magnitude, while Euclidean distance is useful when magnitude is also relevant. Dot product, for its part, offers another similarity perspective that may be more appropriate in certain contexts, such as natural language processing.
These main characteristics do not operate in isolation, but work together to provide a highly efficient data storage and retrieval system. The vector data structure facilitates the application of similarity search algorithms, while different distance calculation methods allow adapting the system to the specific needs of each application. This combination makes vector databases particularly effective in applications requiring semantic searches, personalized recommendations, or any other case where conceptual similarity is more important than exact matching.

Why are Vector Databases used for Embeddings?
Vector databases have become a fundamental tool for handling embeddings for three main reasons: search efficiency, semantic representation capability, and scalability.
Search efficiency is one of the most outstanding characteristics of these databases. Embeddings perform a crucial task by transforming complex data, such as text, images, or audio, into numerical vectors that can be efficiently processed by computers. Vector databases are specifically designed to work with these vectors in multidimensional spaces, making them extraordinarily efficient for performing searches. This capability allows executing fast semantic searches even in massive datasets, something that would be practically impossible with traditional databases.
Semantic representation constitutes another fundamental advantage of this approach. Embeddings have the remarkable ability to capture not only the literal content of data, but also their meaning and the semantic relationships between different elements. When two elements are conceptually similar, their embeddings are also similar in the vector space. This feature allows performing sophisticated conceptual searches, overcoming the limitations of exact match searches. For example, a search for "automobile" could find relevant documents containing words like "car", "vehicle", or "auto", even if the exact term is not present.
Regarding scalability, vector databases demonstrate exceptional performance. They are designed from conception to efficiently handle millions of vectors, implementing highly specialized indexing techniques that allow maintaining fast response times even when the amount of data grows significantly. This ability to scale without degrading performance is crucial in modern applications, where data volume can grow exponentially. Vector databases achieve this through optimized data structures and advanced search algorithms that maintain efficiency even with massive datasets.
The combination of these three characteristics makes vector databases the ideal choice for working with embeddings in artificial intelligence and natural language processing applications. Their ability to efficiently handle large volumes of data, while maintaining semantic accuracy and search speed, makes them an indispensable tool in modern data processing infrastructure.

Technical Considerations in Vector Databases
When implementing and maintaining a vector database, there are several crucial technical considerations we must keep in mind to ensure optimal operation. These considerations focus mainly on three fundamental aspects: indexing, performance, and system maintenance.
Indexing represents one of the fundamental pillars in the operation of a vector database. To perform efficient searches in multidimensional spaces, these databases implement specialized indices that allow organizing and accessing vectors optimally. One of the most used techniques is Locality-Sensitive Hashing (LSH), which allows grouping similar vectors in the same "buckets" or storage spaces, facilitating their subsequent retrieval. Additionally, data structures such as KD-trees and Ball trees are used, which divide the vector space into smaller and more manageable regions, allowing more efficient searches by reducing the number of necessary comparisons.
Vector database performance requires a delicate balance between result accuracy and response speed. This balance is particularly important in applications requiring real-time responses. Index optimization plays a crucial role in this aspect, as a well-designed index can significantly reduce search time without compromising result quality. Efficient memory management is another critical factor, especially when handling large volumes of vector data. It is necessary to implement cache and paging strategies that allow keeping the most frequently accessed data in memory while efficiently managing disk storage.
Vector database maintenance requires constant and systematic attention. Index updates must be performed in a scheduled and efficient manner to maintain optimal system performance, especially when vectors are frequently added or removed. Dimensionality management is a particularly challenging aspect, as working with high-dimensional vectors can lead to problems known as the "curse of dimensionality", where the effectiveness of traditional search algorithms degrades significantly. Finally, continuous performance monitoring is essential to proactively identify and resolve problems, ensuring the database maintains optimal operating levels and responds adequately to application needs.
These technical considerations are not isolated elements, but form part of an interconnected system where each aspect influences the others. For example, a good indexing strategy can significantly improve performance, while adequate maintenance ensures that both indices and performance remain at optimal levels over time. Understanding and properly managing these technical aspects is fundamental to success in implementing and operating a vector database.

2. Main Library Components
The RAG library for Delphi is designed with a modular architecture, facilitating the integration and customization of its functionalities. In this section, the main components are described, their key properties and methods, as well as their relationship with other library elements.
2.1 TAiEmbeddingNode
Description:
TAiEmbeddingNode represents an embedding node that encapsulates vector data, the associated text, and functionalities to calculate semantic similarities between embeddings. This component is essential for working with numerical representations of text and performing similarity searches.
Main Properties:
FData: Contains the embedding vector data.
FText: Stores the original text from which the embedding was generated.
FDim: Dimension of the embedding vector.
FModel: Name of the model used to generate the embedding.
Relevant Methods:
CosineSimilarity(Node: TAiEmbeddingNode): Double
Calculates cosine similarity between two embeddings.
ToJSON: TJSONObject
Converts an embedding to JSON format.
FromJSON(JSON: TJSONObject)
Loads an embedding from a JSON object.
Usage Example:
pascal
Copy code
var
  Node1, Node2: TAiEmbeddingNode;
  Similarity: Double;
begin
  Node1 := TAiEmbeddingNode.Create;
  Node2 := TAiEmbeddingNode.Create;
  
  // Assign data to embeddings
  Node1.FData := [0.1, 0.2, 0.3];
  Node2.FData := [0.1, 0.2, 0.4];
  
  // Calculate cosine similarity
  Similarity := Node1.CosineSimilarity(Node2);
  Writeln('Cosine Similarity: ', Similarity:0:2);
end;

2.2 TAiDataVec
Description:
TAiDataVec acts as a container to handle collections of embeddings. This component allows adding, storing, searching, and retrieving embeddings based on similarities.
Main Properties:
Embeddings: List of stored embeddings.
Index: Internal index for fast searches.
Relevant Methods:
AddEmbedding(Text: String)
Generates an embedding for a given text and adds it to the collection.
Search(SimilarityThreshold: Double; MaxResults: Integer): TArray<TAiEmbeddingNode>
Performs a search for similar embeddings within the index.
SaveToFile(FileName: String)
Saves embeddings to a file.
LoadFromFile(FileName: String)
Loads embeddings from a file.
Usage Example:
pascal
Copy code
var
  DataVec: TAiDataVec;
  Results: TArray<TAiEmbeddingNode>;
begin
  DataVec := TAiDataVec.Create;
  
  // Add embeddings
  DataVec.AddEmbedding('Example text 1');
  DataVec.AddEmbedding('Example text 2');

2.3 TAiEmbeddingIndex
Description:
This component is responsible for indexing and performing efficient searches in embedding collections. The base class TAiEmbeddingIndex can be extended to implement different indexing strategies.
Supported Index Types:
TAIBasicEmbeddingIndex: Cosine similarity-based search.
TAIHNSWIndex: Efficient search in large data volumes.
Relevant Methods:
BuildIndex(Embeddings: TList<TAiEmbeddingNode>)
Builds the index from a list of embeddings.
Search(Query: TAiEmbeddingNode; TopK: Integer): TArray<TAiEmbeddingNode>
Returns the TopK results closest to a query embedding.

2.4 TAiRagChat
Description:
TAiRagChat connects embedding functionality with language models (LLMs). This component integrates queries with additional context provided by retrieved embeddings.
Main Properties:
ChatModel: Interface to interact with a language model.
DataVec: Reference to the embedding container.
Relevant Methods:
QueryWithContext(QueryText: String): String
Performs a query to an LLM adding relevant context.
Usage Example:
var
  RagChat: TAiRagChat;
begin
  RagChat := TAiRagChat.Create;
  
  // Configure model and embeddings
  RagChat.ChatModel := TAiOpenChat.Create('config.json');
  RagChat.DataVec := TAiDataVec.Create;
  
  // Perform a query
  Writeln(RagChat.QueryWithContext('What is the product price?'));
end;
4. Using the Library: Working in Memory
The library components allow handling embeddings directly in memory, which simplifies implementation and eliminates dependency on external databases. This approach is ideal for rapid prototyping scenarios or when the data volume is small.
4.1 In-Memory Workflow
The basic workflow for in-memory RAG is as follows:
Create and manage embeddings using TAiEmbeddingNode and TAiDataVec.
Perform semantic searches using in-memory indices.
Integrate results into RAG queries using TAiRagChat.

4.2 Initial Configuration
Component Initialization:
pascal
Copy code
var
  DataVec: TAiDataVec;
begin
  // Create the embedding container
  DataVec := TAiDataVec.Create;

  // Configure embeddings without external database
  Writeln('In-memory RAG system initialized.');
end;

4.3 Create and Store Embeddings
Embeddings can be generated from plain text and stored in memory within a TAiDataVec.
Example: Add Embeddings from Text
pascal
Copy code
var
  DataVec: TAiDataVec;
begin
  DataVec := TAiDataVec.Create;

  // Add embeddings from texts
  DataVec.AddEmbedding('This is an example text.');
  DataVec.AddEmbedding('Another text that will be used as reference.');
  
  Writeln('Embeddings generated and stored in memory.');
end;

4.4 Search for Similar Embeddings
Once embeddings are generated, the most similar ones can be searched in memory.
Example: Semantic Search
pascal
Copy code
var
  DataVec: TAiDataVec;
  Results: TArray<TAiEmbeddingNode>;
begin
  DataVec := TAiDataVec.Create;

  // Add texts as embeddings
  DataVec.AddEmbedding('Test text 1.');
  DataVec.AddEmbedding('Example text 2.');

  // Search for similarity with a new text
  Results := DataVec.Search('Text to search for similarities.', 0.75, 5);

  // Show results
  Writeln('Similar embeddings found: ', Length(Results));
end;

4.5 RAG Queries with Context
With TAiRagChat, you can integrate search results into enriched RAG queries.
Example: RAG Queries without Database
pascal
Copy code
var
  RagChat: TAiRagChat;
  DataVec: TAiDataVec;
  Response: String;
begin
  DataVec := TAiDataVec.Create;
  RagChat := TAiRagChat.Create;

  // Configure components
  RagChat.DataVec := DataVec;

  // Add embeddings to the in-memory container
  DataVec.AddEmbedding('This is important contextual data.');
  DataVec.AddEmbedding('Another relevant context for the system.');

  // Perform query with context
  Response := RagChat.QueryWithContext('What information do you have about the system?');
  Writeln('AI Response: ', Response);
end;

Advantages of In-Memory Work
Simplicity: No additional configuration or external database connection required.
Speed: Ideal for fast queries on small data volumes.
Portability: The system works entirely in memory, making it easy to distribute and test.

Limitations of In-Memory Work
Scalability: RAM limits the number of embeddings that can be handled.
Persistence: Data is not stored between executions; it must be reloaded if closed.
Search Performance: Although efficient for small volumes, in-memory search may not be optimal for large datasets.
