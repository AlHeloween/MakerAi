FLUENT GRAPH BUILDER DOCUMENTATION
MakerAI Suite - Code-based Orchestration Construction

1. Introduction
The Fluent Graph Builder is a mechanism that allows creating orchestrations, workflows, and agent graphs through readable Delphi code, using a fluent style (Fluent API) that avoids manually creating nodes, edges, and configurations.
The objective is to allow a programmer to build a complete flow using instructions like:
Graph.Build
  .Node('ReadInvoice').Tool<TReadInvoiceTool>
  .Node('ExtractData').Tool('TExtractorTool')
  .Decision('Validation', 'Blackboard.Total > 0')
    .OnTrue('Continue')
    .OnFalse('Abort')
  .Node('Continue').Tool<TRagVectorSearchTool>
  .Node('GenerateResponse').Tool<TLLMTool>
  .EndNode('End')
  .Compile;
This system is fully integrated with:
EngineRegistry
Metadata (TToolAttribute)
Schemas generated by RTTI
Existing Tools and Engines in MakerAI Suite

2. Fundamental Concepts
2.1 Graph
Represents the complete orchestration, composed of nodes and connections.
2.2 Node
Each step of the flow. It can be:
Execution node (Tool)
Decision node (condition)
Start or end node
Fork/parallel node
Subgraph node
2.3 Tool
An executable component (class inheriting from TAiToolBase) that contains:
Operation to execute
Parameters (RTTI schema)
Metadata captured by TToolAttribute
Registry key in EngineRegistry
2.4 EngineRegistry
Automatically registers:
Tool class name
Unit name
Category
Parameters
Schema
Exposed methods
The Fluent Builder uses EngineRegistry to:
Resolve Tool by name
Resolve Tool class by generic
Automatically obtain node schema

3. The Fluent Builder
The system is implemented in the class:
TAiGraphBuilder
This class exposes a set of chainable methods that allow building the graph.

4. Usage Cycle
1. Create an empty graph
var Graph := TAiGraph.Create;
2. Start the builder
Graph.Build
3. Chain nodes and tools
  .Node('ReadFile').Tool<TReadInvoiceTool>
  .Node('ExtractData').Tool('TExtractorTool')
4. Define control logic
  .Decision('IsValid', 'Invoices.Total > 0')
    .OnTrue('Process')
    .OnFalse('Abort')
5. Close the graph
  .EndNode('End')
  .Compile;

5. Available Methods

5.1 StartNode(const AName: string)
Sets the initial node of the flow.
.Build.StartNode('Start')

5.2 Node(const AName: string)
Creates a general node.
.Node('Extract')
After a Node, a Tool is normally chained.

5.3 Tool<T: TAiToolBase>
Assigns a Tool using generic type.
.Node('ReadInvoice')
  .Tool<TReadInvoiceTool>
What it does internally:
Registers the class in the node.
Obtains the schema automatically from EngineRegistry.
Assigns category, description, and metadata.
Automatically connects to the previous node.

5.4 Tool(const AToolName: string)
Assigns a Tool using its textual name.
.Node('Extract')
  .Tool('TExtractorTool')
The Builder will search for the Tool inside EngineRegistry.

5.5 Decision(const AName, ACondition: string)
Creates a decision node based on a boolean expression.
.Decision('Validate', 'Blackboard.Total > 0')

5.6 OnTrue(const NextNode: string)
Connects the TRUE output of a decision node.
.OnTrue('Continue')
5.7 OnFalse(const NextNode: string)
Connects the FALSE output.
.OnFalse('Abort')

5.8 Fork(const AName: string)
Executes several paths in parallel.
.Fork('ParallelProcesses')

5.9 Join(const AName: string)
Waits for parallel paths to finish.

5.10 SubGraph(const AName: string; ACallback: TProc<TAiGraphBuilder>)
Allows building nested flows.
.SubGraph('Preprocessing',
  procedure(G: TAiGraphBuilder)
  begin
    G.Node('Step1').Tool<TStep1Tool>;
    G.Node('Step2').Tool<TStep2Tool>;
  end)

5.11 EndNode(const AName: string)
Indicates the end of the flow.

5.12 Compile
Validates and generates:
Internal connections
Resolution of missing nodes
Graph optimization
Preparation for execution by the Engine
It is the mandatory final step.

6. How EngineRegistry integration works
When the programmer calls:
.Node('ExtractData').Tool<TExtractorTool>
The builder:
Obtains the TExtractorTool class.
Uses EngineRegistry to:
Confirm the Tool is registered
Obtain:
Unit name
Category
Description
Structured schema
Automatically assigns the schema to the node.
Creates the connection to the previous node.
Registers the Tool internally for compilation.

7.1 Simple linear flow
Graph.Build

  .Node('ExtractData')
    .Tool('TExtractorTool')

7.2 Flow with decision
Graph.Build
  .StartNode('Load')

  .Node('Analyze')
    .Tool<TAnalyzerTool>

  .Decision('IsValid', 'Result.Validated = True')
    .OnTrue('Process')
    .OnFalse('Abort')

  .Node('Process')
    .Tool<TProcessInvoiceTool>

  .Node('Abort')
    .Tool<TLogTool>

  .EndNode('End')
  .Compile;

7.3 Flow with parallelism
Graph.Build
  .StartNode('Start')

  .Fork('Parallel')
    .Branch('Clean').Tool<TCleanTool>
    .Branch('Index').Tool<TIndexTool>
    .Branch('Embeddings').Tool<TEmbeddingTool>

  .Join('Unite')

  .Node('Finalize').Tool<TLLMTool>
  .EndNode('End')
  .Compile;

OFFICIAL DOCUMENTATION - MakerAI Engine Registry & Fluent Execution
1. Introduction
The Engine Registry is the core of the MakerAI ecosystem.
Its mission is to:
Discover tools through RTTI
Register their metadata (class, unit, attributes, schema)
Instantiate them dynamically
Provide this information to the Builder to build AI flows, agents, and pipelines
The registry does not execute, but is a centralized catalog of capabilities.
The current code implements precisely this responsibility.

2. What problem does it solve?
In a modular AI system, we cannot code direct references to classes:
MyTool := TMyTool.Create; // ❌ not scalable
Instead, the Engine must be able to:
Discover all available tools
Create instances on demand by name
Expose metadata to dynamic components (GraphEngine, visual Designer, Fluent Builder)
Guarantee that tools are built from the Engine, not from the application

3. Engine Registry Architecture
📌 3.1 TToolInfo
Registers:
Delphi class
Unit where it is found (necessary for code generators)
TToolInfo = record
  ToolClass: TClass;
  UnitName: string;
end;

📌 3.2 Singleton Registry
TEngineRegistry = class
private
  FRegisteredTools: TDictionary<string, TToolInfo>;
The registry is initialized automatically in initialization.

📌 3.3 Tool Registration
procedure TEngineRegistry.RegisterTool(ToolClass: TClass; const AUnitName: string);
The programmer only needs to call:
Engine.Registry.RegisterTool(TCodeAnalyzerTool, 'uCodeAnalyzer');
Engine.Registry.RegisterTool(TFunctionalTestGenTool, 'uFuncTestGen');

📌 3.4 Tool Search
FindToolClass('TCodeAnalyzerTool') → TClass
GetUnitForToolClass('TCodeAnalyzerTool') → 'uCodeAnalyzer'

📌 3.5 Automatic Blueprint JSON Generation
The registry inspects:
Class attributes (TToolAttribute)
Property attributes (TToolParameterAttribute)
Delphi types → JSON types
Automatically generating:
{
  "name": "FormatCode",
  "description": "Applies auto-formatting",
  "schema": {
    "properties": {
      "Indent": { "type": "integer", "default": 2 }
    }
  }
}

4. Integration with Fluent Builder
The Fluent Builder does NOT create tools directly.
It always uses Engine Registry.
🔧 Fluent Example:
Engine.Flow
  .UseTool('CodeAnalyzer')
  .UseTool('FunctionalTestGen')
  .Goal('Audit and generate tests for module X')
  .Run;
The Builder will do:
Tool := Engine.Registry.FindToolClass('FunctionalTestGen').Create;
5. How are components created from the Engine?
You must define in your main Engine:
function TMakerEngine.CreateTool(const Name: string): TAiToolBase;
var
  ToolClass: TClass;
begin
  ToolClass := Registry.FindToolClass(Name);
  Result := TAiToolBase(ToolClass.Create);
end;
And then:
Tool := Engine.CreateTool('FunctionalTestGen');

1. Practical problem: Automatic code auditor + functional test generation
We want to build an agent that:
Receives a Delphi code fragment.
Uses AI to audit it and detect:
errors,
bad practices,
style problems,
vulnerabilities.
Decides, depending on severity:
HIGH → generate a proposed fix and compile it.
MEDIUM → generate a detailed issue.
LOW → register a log.
If severity was high, also:
creates a functional test in Delphi,
compiles it with the inline compiler,
sends the result to the user.
This flow requires decisions, multiple tools, and conditional execution.

uses
  uMakerAi.GraphBuilder,
  uMakerAi.Agents.EngineRegistry,
  uMakerAi.Agents;

procedure Build_AuditFlow(const Engine: TMakerEngine);
var
  Flow: TFlowBuilder;
begin
  Flow := TFlowBuilder.Create(Engine);
  try
    Flow.DefineFlow('CodeAuditFlow')

      // 1. Initial node: audits the code
      .Add('AnalyzeCode').UsingTool('CodeAudit')
        .When('severity = "high"').GoTo('FixCode')
        .When('severity = "medium"').GoTo('CreateIssue')
        .When('severity = "low"').GoTo('LogResult')
        .Otherwise.GoTo('LogResult')   // defensive fallback

      // 2. High severity: generate fix
      .Add('FixCode').UsingTool('FixCodeTool')
        .Next('GenerateTest')

      // 3. Create issue if severity is medium
      .Add('CreateIssue').UsingTool('CreateIssueTool')
        .Next('End')

      // 4. Register if mild
      .Add('LogResult').UsingTool('Logger')
        .Next('End')

      // 5. Build functional test
      .Add('GenerateTest').UsingTool('GenerateTestTool')
        .Next('Compile')

      // 6. Compile test + fix
      .Add('Compile').UsingTool('CompileDelphi')
        .Next('End')

      // Final node
      .Add('End');

    // Now we build the graph
    Flow.Build;
  finally
    Flow.Free;
  end;
end;

Unit: uMakerAi.Demo.CodeAuditor.pas
unit uMakerAi.Demo.CodeAuditor;

interface

uses
  System.SysUtils, System.Classes, System.JSON;

/// <summary>
/// Executes an audit flow on a Delphi code fragment.
/// - ACode: source code to audit
/// - AOptions: optional JSON with parameters (e.g., {"maxSeverity":"medium"})
/// Returns a JSON-string with the consolidated result.
/// </summary>
function AuditCodeDemo(const ACode: string; AOptions: TJSONObject = nil): string;

implementation

uses
  System.Rtti, System.TypInfo, System.Generics.Collections,
  uMakerAi.Agents.EngineRegistry, uMakerAi.Agents;

{ RTTI Helpers }

procedure TrySetToolStringProp(ATool: TObject; const APropName: string; const AValue: string);
var
  Ctx: TRttiContext;
  RType: TRttiType;
  Prop: TRttiProperty;
begin
  if not Assigned(ATool) then
    Exit;
  Ctx := TRttiContext.Create;
  try
    RType := Ctx.GetType(ATool.ClassType);
    Prop := RType.GetProperty(APropName);
    if Assigned(Prop) and Prop.IsWritable then
      if Prop.PropertyType.TypeKind in [tkString, tkUString, tkLString, tkWString] then
        Prop.SetValue(ATool, AValue);
  finally
    Ctx.Free;
  end;
end;

procedure TrySetToolIntegerProp(ATool: TObject; const APropName: string; AValue: Integer);
var
  Ctx: TRttiContext;
  RType: TRttiType;
  Prop: TRttiProperty;
begin
  if not Assigned(ATool) then
    Exit;
  Ctx := TRttiContext.Create;
  try
    RType := Ctx.GetType(ATool.ClassType);
    Prop := RType.GetProperty(APropName);
    if Assigned(Prop) and Prop.IsWritable then
      if Prop.PropertyType.TypeKind in [tkInteger, tkInt64] then
        Prop.SetValue(ATool, TValue.From<Integer>(AValue));
  finally
    Ctx.Free;
  end;
end;

procedure TrySetToolBooleanProp(ATool: TObject; const APropName: string; AValue: Boolean);
var
  Ctx: TRttiContext;
  RType: TRttiType;
  Prop: TRttiProperty;
begin
  if not Assigned(ATool) then
    Exit;
  Ctx := TRttiContext.Create;
  try
    RType := Ctx.GetType(ATool.ClassType);
    Prop := RType.GetProperty(APropName);
    if Assigned(Prop) and Prop.IsWritable then
      if Prop.PropertyType.TypeKind = tkEnumeration then
        if Prop.PropertyType.Handle = TypeInfo(Boolean) then
          Prop.SetValue(ATool, TValue.From<Boolean>(AValue));
  finally
    Ctx.Free;
  end;
end;

/// Attempts to set the first valid property name from the array (wildcard for different names)
procedure TrySetFirstStringProp(ATool: TObject; const Names: array of string; const Value: string);
var
  i: Integer;
begin
  for i := 0 to High(Names) do
  begin
    TrySetToolStringProp(ATool, Names[i], Value);
  end;
end;

function CreateToolInstanceByName(const AClassName: string): TAiToolBase;
var
  LClass: TClass;
  LCompClass: TComponentClass;
begin
  Result := nil;
  LClass := TEngineRegistry.Instance.FindToolClass(AClassName);
  if not Assigned(LClass) then
    Exit;
  // Tools are TComponent descendants; we create with owner = nil
  LCompClass := TComponentClass(LClass);
  Result := TAiToolBase(LCompClass.Create(nil));
end;

function MergeToJSONString(const AObj: TJSONObject): string;
begin
  if Assigned(AObj) then
    Result := AObj.ToString
  else
    Result := '{}';
end;

function AuditCodeDemo(const ACode: string; AOptions: TJSONObject = nil): string;
var
  JsonOut: TJSONObject;
  AuditTool, FixTool, TestTool, CompileTool, IssueTool, LoggerTool: TAiToolBase;
  sAuditOut, sFixOut, sTestSource, sCompileOut, sIssueOut, sLogOut: string;
  LSeverity: string;
  MaxSeverity: string;
  // small local func to safe free tools
  procedure FreeTool(var T: TAiToolBase);
  begin
    if Assigned(T) then
    begin
      T.Free;
      T := nil;
    end;
  end;
begin
  JsonOut := TJSONObject.Create;
  AuditTool := nil; FixTool := nil; TestTool := nil; CompileTool := nil; IssueTool := nil; LoggerTool := nil;
  sAuditOut := ''; sFixOut := ''; sTestSource := ''; sCompileOut := ''; sIssueOut := ''; sLogOut := '';
  LSeverity := 'unknown';
  MaxSeverity := '';

  try
    // Read options
    if Assigned(AOptions) then
      MaxSeverity := AOptions.GetValue<string>('maxSeverity', '');

    // 1) Create tools from EngineRegistry
    AuditTool := CreateToolInstanceByName('CodeAudit');
    FixTool   := CreateToolInstanceByName('FixCode');
    TestTool  := CreateToolInstanceByName('GenerateTest');
    CompileTool:= CreateToolInstanceByName('CompileDelphi');
    IssueTool := CreateToolInstanceByName('CreateIssue');
    LoggerTool:= CreateToolInstanceByName('Logger');

    // Validations
    if not Assigned(AuditTool) then
    begin
      JsonOut.AddPair('error', 'Tool CodeAudit not found in EngineRegistry.');
      Exit(MergeToJSONString(JsonOut));
    end;

    // 2) Execute CodeAudit
    // We try to provide input by common properties or as direct parameter to Run.
    TrySetFirstStringProp(AuditTool, ['Code', 'Source', 'Input', 'SourceCode'], ACode);

    try
      sAuditOut := '';
      AuditTool.Run(nil, ACode, sAuditOut);
    except
      on E: Exception do
      begin
        JsonOut.AddPair('error', 'CodeAudit failed: ' + E.Message);
        Exit(MergeToJSONString(JsonOut));
      end;
    end;

    // Audit tool should return structured text (by convention: JSON or similar)
    JsonOut.AddPair('auditOutput', sAuditOut);

    // We try to extract severity from output if it comes in JSON
    try
      var tmp := TJSONObject.ParseJSONValue(sAuditOut);
      if Assigned(tmp) and (tmp is TJSONObject) then
      begin
        var jObj := tmp as TJSONObject;
        LSeverity := jObj.GetValue<string>('severity', LSeverity);
        // if there is a "report" we add it
        var rep := jObj.GetValue('report');
        if Assigned(rep) then
          JsonOut.AddPair('auditReport', rep.Clone as TJSONValue)
        else
          JsonOut.AddPair('auditReport', TJSONString.Create(sAuditOut));
        tmp.Free;
      end
      else
      begin
        // not JSON: we leave it as raw text
        JsonOut.AddPair('auditReport', TJSONString.Create(sAuditOut));
      end;
    except
      // parse error: we save raw output
      JsonOut.AddPair('auditReport', TJSONString.Create(sAuditOut));
    end;

    // 3) Decision by severity
    // For simplicity, we normalize to lower-case
    LSeverity := LSeverity.ToLower.Trim;
    if LSeverity = '' then
      LSeverity := 'unknown';

    JsonOut.AddPair('severity', LSeverity);

    // Branching:
    if LSeverity = 'high' then
    begin
      // a) Generate fix
      if Assigned(FixTool) then
      begin
        TrySetFirstStringProp(FixTool, ['Code','Source','Input','SourceCode'], sAuditOut);
        try
          FixTool.Run(nil, sAuditOut, sFixOut);
        except
          on E: Exception do
            sFixOut := 'FixTool failed: ' + E.Message;
        end;
        JsonOut.AddPair('fix', TJSONString.Create(sFixOut));
      end;

      // b) Generate functional test from fix (or original code if fix empty)
      if Assigned(TestTool) then
      begin
        var testInput := sFixOut;
        if testInput.Trim.IsEmpty then
          testInput := ACode;
        TrySetFirstStringProp(TestTool, ['Code','Source','Input','SourceCode'], testInput);
        try
          TestTool.Run(nil, testInput, sTestSource);
        except
          on E: Exception do
            sTestSource := 'GenerateTest failed: ' + E.Message;
        end;
        JsonOut.AddPair('generatedTest', TJSONString.Create(sTestSource));
      end;

      // c) Compile test
      if Assigned(CompileTool) then
      begin
        TrySetFirstStringProp(CompileTool, ['ProgramSource','Source','Code','Input','Program'], sTestSource);
        try
          CompileTool.Run(nil, sTestSource, sCompileOut);
        except
          on E: Exception do
            sCompileOut := 'CompileTool failed: ' + E.Message;
        end;
        JsonOut.AddPair('compileOutput', TJSONString.Create(sCompileOut));
      end;

      // d) Final result
      JsonOut.AddPair('status', 'fix_generated_and_compiled');
    end
    else if LSeverity = 'medium' then
    begin
      // Generate issue
      if Assigned(IssueTool) then
      begin
        TrySetFirstStringProp(IssueTool, ['Code','Source','Input','Description','Report'], sAuditOut);
        try
          IssueTool.Run(nil, sAuditOut, sIssueOut);
        except
          on E: Exception do
            sIssueOut := 'CreateIssue failed: ' + E.Message;
        end;
        JsonOut.AddPair('issueResult', TJSONString.Create(sIssueOut));
      end;
      JsonOut.AddPair('status', 'issue_created');
    end
    else // low / unknown
    begin
      if Assigned(LoggerTool) then
      begin
        TrySetFirstStringProp(LoggerTool, ['Message','Log','Input','Description'], sAuditOut);
        try
          LoggerTool.Run(nil, sAuditOut, sLogOut);
        except
          on E: Exception do
            sLogOut := 'Logger failed: ' + E.Message;
        end;
        JsonOut.AddPair('logResult', TJSONString.Create(sLogOut));
      end;
      JsonOut.AddPair('status', 'logged_or_no_action');
    end;

    // We return the complete JSON as string
    Result := MergeToJSONString(JsonOut);
  finally
    // free tools (if created)
    FreeTool(AuditTool);
    FreeTool(FixTool);
    FreeTool(TestTool);
    FreeTool(CompileTool);
    FreeTool(IssueTool);
    FreeTool(LoggerTool);
    JsonOut.Free;
  end;
end;

end.

Notes and recommendations
Tool names: check that the names used in CreateToolInstanceByName exactly match the RegisterTool of EngineRegistry. If in your project you use names like TCodeAuditTool or TAuditCodeTool, change the string in the demo.
Input properties: the function tries to set common properties (Code, Source, Input, SourceCode) on each tool. If your Tools use other names, add those names in TrySetFirstStringProp.
CodeAudit output format: the demo expects CodeAudit.Run to return preferably a JSON with the severity property ("high"|"medium"|"low"). If your tool returns another format, adapt the parsing.
Security: executing inline compilers or executing binaries has security implications; consider sandboxing and input validation.
Extension: if you want the AuditCodeDemo function to use the real graph (TAIAgents) and its links/conditions, I can adapt the function to build the graph and execute it through TAIAgents.Run instead of executing tools sequentially as this demo does.

Tool | Description
CodeAudit | LLM that audits code and returns { severity, issues, suggestion }
FixCode | LLM that generates a corrected version of the code
GenerateTest | AI that creates a functional test in Delphi
CompileDelphi | Tool that executes the inline compiler and returns the result
CreateIssue | Sends the issue description to the system used by the team
Logger | Registers flow information
