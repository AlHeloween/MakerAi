MakerAI AutoAgents — Demo 02: SingleTool
How to create, register and use a custom tool in TLLMNode
1. Introduction
Demo 02 introduces the concept of tools in the MakerAI agent system. A tool is a function that the LLM model can invoke during its reasoning to obtain information or perform calculations it cannot do directly.
In this demo the agent has an arithmetic calculator. When the user asks a math question, the LLM decides on its own when to call it, interprets the result and formulates the final answer. This cycle is called the ReAct cycle (Reasoning + Acting).
Graph structure:
   [Start] ——lmFanout——> [CalculatorAgent (TLLMNode)] ——lmFanout——> [End]
The Start and End nodes are simple TAIAgentsNode without their own logic — they act as input and output gateways.
2. The IAiTool Interface
Every tool compatible with TLLMNode must implement the IAiTool interface, defined in uMakerAi.Agents.IAiTool.pas:
IAiTool = interface
  function GetName        : String;          // Unique name (e.g., "calculator")
  function GetDescription : String;          // Description for the LLM
  function GetCategory    : String;          // Optional logical grouping
  function GetSchema      : TJSONObject;     // JSON parameter schema
  function Execute(const AArgs: TJSONObject): TJSONObject;
  function IsAvailable    : Boolean;         // True = tool active
end;




Important members:
•  GetName — unique identifier without spaces. The LLM uses it in tool_call. E.g., "calculator".
•  GetDescription — natural language description. The LLM reads it to decide when to use the tool.
•  GetSchema — TJSONObject with the JSON Schema of arguments. Do not free the returned object; it is owned by the tool.
•  Execute — receives arguments from the LLM as TJSONObject and returns a TJSONObject with the result. TLLMNode frees both.
•  IsAvailable — return False to temporarily disable without removing from the registry.
3. Implement TCalculatorTool Step by Step
3.1  Declare the Class
The tool inherits from TInterfacedObject and implements IAiTool. The schema is built once in the constructor and reused:
type
  TCalculatorTool = class(TInterfacedObject, IAiTool)
  private
    FSchema: TJSONObject;
  public
    constructor Create;
    destructor  Destroy; override;
    function GetName        : String;
    function GetDescription : String;
    function GetCategory    : String;
    function GetSchema      : TJSONObject;
    function Execute(const AArgs: TJSONObject): TJSONObject;
    function IsAvailable    : Boolean;
  end;
3.2  Build the JSON Schema in the Constructor
The schema defines what parameters the tool accepts. This schema exposes three: operation (enum of operations), a and b (numbers):
constructor TCalculatorTool.Create;
var Props, Op, Num : TJSONObject;
    Enum, Req      : TJSONArray;
begin
  inherited Create;
  FSchema := TJSONObject.Create;
  FSchema.AddPair('type', 'object');
  Props := TJSONObject.Create;

  // "operation": string with enum
  Op := TJSONObject.Create;
  Op.AddPair('type', 'string');
  Op.AddPair('description', 'Arithmetic operation to perform');
  Enum := TJSONArray.Create;
  Enum.Add('add'); Enum.Add('subtract');
  Enum.Add('multiply'); Enum.Add('divide');
  Op.AddPair('enum', Enum);
  Props.AddPair('operation', Op);

  // "a" and "b": numeric operands
  Num := TJSONObject.Create;
  Num.AddPair('type', 'number'); Num.AddPair('description', 'First operand');
  Props.AddPair('a', Num);
  Num := TJSONObject.Create;
  Num.AddPair('type', 'number'); Num.AddPair('description', 'Second operand');
  Props.AddPair('b', Num);

  FSchema.AddPair('properties', Props);
  Req := TJSONArray.Create;
  Req.Add('operation'); Req.Add('a'); Req.Add('b');
  FSchema.AddPair('required', Req);
end;

destructor TCalculatorTool.Destroy;
begin
  FSchema.Free;   // FSchema is ours; we must free it here
  inherited;
end;
3.3  Implement Execute
Execute receives the arguments generated by the LLM, performs the operation and returns the result. TLLMNode frees both JSON objects (AArgs and Result):
function TCalculatorTool.Execute(const AArgs: TJSONObject): TJSONObject;
var Op       : String;
    A, B, Res: Double;
begin
  Result := nil;
  if not Assigned(AArgs) then Exit;
  AArgs.TryGetValue<String>('operation', Op);
  AArgs.TryGetValue<Double>('a', A);
  AArgs.TryGetValue<Double>('b', B);
  Res := 0;
  if      Op = 'add'      then Res := A + B
  else if Op = 'subtract' then Res := A - B
  else if Op = 'multiply' then Res := A * B
  else if Op = 'divide'   then begin
    if B = 0 then begin
      Result := TJSONObject.Create;
      Result.AddPair('error', 'Division by zero');
      Exit;
    end;
    Res := A / B;
  end;
  Result := TJSONObject.Create;
  Result.AddPair('result', TJSONNumber.Create(Res));
end;
3.4  Identification Methods
function TCalculatorTool.GetName        : String; begin Result := 'calculator'; end;
function TCalculatorTool.GetDescription : String; begin Result := 'Performs add, subtract, multiply or divide on two numbers'; end;
function TCalculatorTool.GetCategory    : String; begin Result := 'Math'; end;
function TCalculatorTool.GetSchema      : TJSONObject; begin Result := FSchema; end;
function TCalculatorTool.IsAvailable    : Boolean; begin Result := True; end;
4. Register the Tool in TAiToolRegistry
TAiToolRegistry is a global singleton that acts as a catalog of available tools. TLLMNode queries it at the start of each DoExecute to load active tools into the chat:
// Register BEFORE creating the Manager
TAiToolRegistry.Instance.Register(
  TCalculatorTool.Create,   // instance; registry takes ownership
  'local',                // origin: 'local', 'mcp', 'remote', etc.
  'math'                  // optional category
);
Important notes:
•  The registry takes ownership — do not call .Free on the registered instance.
•  If two tools are registered with the same name, the second replaces the first.
•  UseAllTools = True in TLLMNode injects all of TAiToolRegistry.Instance.
•  To isolate tools between nodes, create your own registry and assign it to TLLMNode.Registry.
5. Configure the Graph: Start -> LLMNode -> End
The minimum graph pattern for an agent with tools uses three nodes. Start and End are passthrough nodes (no OnExecute): the framework does Output := Input automatically:
Manager := TAIAgentManager.Create(nil);
Manager.Asynchronous := False;
Manager.TimeoutMs    := 60000;

// Input node (passthrough)
StartNode       := TAIAgentsNode.Create(Manager);
StartNode.Name  := 'Start';
StartNode.Graph := Manager;

// LLM Node with tools
LLMNode              := TLLMNode.Create(Manager);
LLMNode.Name         := 'CalculatorAgent';
LLMNode.Graph        := Manager;
LLMNode.DriverName   := 'Claude';
LLMNode.Model        := 'claude-haiku-4-5-20251001';
LLMNode.ApiKey       := '@CLAUDE_API_KEY';
LLMNode.UseAllTools  := True;
LLMNode.SystemPrompt := 'You are a math assistant. ALWAYS use the calculator tool.';

// Output node (passthrough)
EndNode       := TAIAgentsNode.Create(Manager);
EndNode.Name  := 'End';
EndNode.Graph := Manager;

// Connect and compile
Manager.AddEdge('Start', 'CalculatorAgent');
Manager.AddEdge('CalculatorAgent', 'End');
Manager.StartNode := StartNode;
Manager.EndNode   := EndNode;
Manager.Compile;

Key TLLMNode Properties:
•  DriverName — LLM provider: "Claude", "OpenAI", "Gemini", "Ollama", etc.
•  Model — specific model. Empty = uses driver default.
•  ApiKey — accepts the @ENV_VAR_NAME convention to resolve from environment variables.
•  UseAllTools — True: injects all tools from TAiToolRegistry.Instance.
•  Registry — assign your own registry to isolate tools. nil = global singleton.
6. Execute the Agent
To launch independent queries, call Manager.Blackboard.Clear before each Manager.Run. This frees the previous AskMsg and allows Run to create a fresh message:
procedure RunQuery(Manager: TAIAgentManager; const AQuestion: String);
begin
  Manager.Blackboard.Clear;          // essential between questions
  Writeln('Question: ', AQuestion);
  Writeln('Answer: ', Manager.Run(AQuestion));
end;

Why Blackboard.Clear? TAIAgentManager.Run has an internal guard: it only creates a new AskMsg if the previous one is nil. Without Clear, subsequent calls recycle the first query's prompt.
7. The ReAct Cycle in Detail
Example: "How much is (100 + 200) / 15?" The loop is transparent; managed by the provider's native function calling inside TAiChatConnection:
Step 1 — THINK    The LLM receives the question and tool definitions.
Step 2 — CALL     tool_call: calculator({ "operation":"add", "a":100, "b":200 })
Step 3 — EXECUTE  TCalculatorTool.Execute -> { "result": 300 }
Step 4 — OBSERVE  tool_result { "result": 300 } returned to the LLM.
Step 5 — CALL     tool_call: calculator({ "operation":"divide", "a":300, "b":15 })
Step 6 — EXECUTE  TCalculatorTool.Execute -> { "result": 20 }
Step 7 — RESPOND  "Result: (100 + 200) / 15 = 20"
TLLMNode publishes the output in the Blackboard under the key NodeName.output:
Manager.Blackboard.GetString('CalculatorAgent.output')  // reads the result
8. Checklist — Key Points
•  Implement IAiTool: GetName, GetDescription, GetSchema and Execute.
•  GetSchema returns FSchema (owned by the tool) — the caller does NOT free it.
•  Execute returns TJSONObject. TLLMNode frees AArgs and the result.
•  Register with TAiToolRegistry.Instance.Register(...) before Compile.
•  Activate UseAllTools := True in TLLMNode to inject the registry.
•  Use the minimum graph: Start -> LLMNode -> End with Manager.AddEdge.
•  Call Manager.Blackboard.Clear between independent queries.
•  Node output is in Blackboard["NodeName.output"] for other nodes.

9. Internal Cycle: How Function Calling Works
When a TLLMNode executes with registered tools, the framework automatically generates a Function Calling type call to the LLM model. The developer does not need to implement anything additional: the complete cycle is transparent.

9.1 Phase 1 – Registration and Schema Preparation
When a tool is registered with TAiToolRegistry.Instance.Register(), the framework stores the instance and its metadata. When TLLMNode executes, the following call chain occurs:
TAiToolRegistry.Instance.Register(TCalculatorTool.Create, ...)
    ↓
TLLMNode.LoadRegistryTools
    ↓
TAiFunctions.Add(TFunctionActionItem)
    Name        = tool.GetName()
    Description = tool.GetDescription()
    Parameters  = tool.GetSchema()   <- JSON Schema (properties, types)
    OnCallFunction = Self.HandleToolCall  <- callback

9.2 Phase 2 – Send to LLM with Tool Definitions
TLLMNode assigns the TAiFunctions to TAiChatConnection and calls AddMessageAndRun(). Internally RunNew calls GetTools(tfClaude/tfOpenAI/tfGemini) which serializes the schemas to each API's specific format, and includes them in the HTTP POST:
Chat.AiFunctions := Functions
Chat.AddMessageAndRun(prompt, 'user', [])
    ↓
RunNew → InternalRunCompletions
    ↓
HTTP POST with:
  {
    "messages": [...],
    "tools": [
      { "name": "calculate", "description": "...",
        "input_schema": { "expression": { "type": "string" } } }
    ]
  }

9.3 Phase 3 – The LLM Decides to Call a Tool
If the LLM considers it needs to use a tool, it responds with stop_reason = "tool_use" instead of generating text directly. The provider driver detects this in ParseChat and creates TAiToolsFunction objects:
LLM responds:
  stop_reason = "tool_use"
  content: [
    { "type": "tool_use", "id": "toolu_abc",
      "name": "calculate", "input": { "expression": "2 + 2" } }
  ]
    ↓
ParseChat detects "tool_use"
    ↓
Creates TAiToolsFunction { Id="toolu_abc", Name="calculate",
                        Arguments='{"expression":"2+2"}' }
    ↓
DoCallFunction(TC)   <- in TTask in parallel if multiple tool_use

9.4 Phase 4 – Actual Tool Execution
DoCallFunction delegates to TAiFunctions, which locates the TFunctionActionItem by name and fires the HandleToolCall callback of TLLMNode. That's where the real tool's Execute() method is invoked:
TAiClaudeChat.DoCallFunction(TC)
    ↓
AiFunctions.DoCallFunction(ToolCall)
    ↓
HandleToolCall callback (in TLLMNode)
    ↓
TAiToolRegistry.TryFind("calculate", Tool)
Result := Tool.Execute(ArgsJSON)   <- TJSONObject with the result
ToolCall.Response := Result.ToString  <- "4"

9.5 Phase 5 – Result Back to the LLM
The result of Execute() is stored in ToolCall.Response. GetMessages() automatically adds a tool_result message to the history with the corresponding tool_use_id. Then InternalRunCompletions is called again with the updated history:
ToolCall.Response = "4"
    ↓
GetMessages() now includes:
  { "role": "user", "content": [
      { "type": "tool_result", "tool_use_id": "toolu_abc",
        "content": "4" }
  ]}
    ↓
InternalRunCompletions is called again with updated history

9.6 Phase 6 – Final Response and ReAct Loop
With the result available, the LLM generates the final response in natural language (stop_reason = "end_turn"). If the answer requires more than one tool, Phases 3–5 repeat automatically until the model produces end_turn. This pattern is called the ReAct loop (Reasoning + Acting):
LLM receives tool_result
    ↓
stop_reason = "end_turn"  <- generates final text
    ↓
ParseChat → DoData/DoDataEnd events
    ↓
TLLMNode.HandleData → FResponse accumulates text
    ↓
Blackboard.SetString('LLMNode.output', FResponse)
    ↓
Graph continues to next node

Note: if more tools are needed, Phases 3-5 cycle repeats
      until stop_reason = "end_turn"

9.7 Complete Cycle Diagram
The following diagram shows the complete flow from tool registration to the LLM's final response:
IAiTool.GetSchema()
        ↓
TAiFunctions (tool definitions)
        ↓
GetTools(tfClaude) → HTTP POST /messages  [tools array]
        ↓
   LLM API
        ↓
stop_reason="tool_use"  +  tool_use block
        ↓
ParseChat → TAiToolsFunction → DoCallFunction
        ↓
HandleToolCall → IAiTool.Execute(args)
        ↓
ToolCall.Response = result
        ↓
HTTP POST /messages  [tool_result]
        ↓
   LLM API
        ↓
stop_reason="end_turn"  →  final text

In summary: the GetSchema() schema becomes the tools array in the API request. The LLM decides when to call them. DoCallFunction executes IAiTool.Execute() and the result returns to the LLM as tool_result. The loop continues until end_turn. This entire cycle is completely transparent to the developer.
